01

Logique d'IA

Agent analyste (Claude). À chaque passe, il récupère les titres d'actualité des trois derniers jours par sous-jacent via l'API News d'Alpaca et demande à Claude Haiku un verdict par ticker : favorable, neutre ou défavorable pour vendre de la prime cette semaine. Un verdict défavorable — résultats trimestriels imminents, litige, choc, M&A — écarte le sous-jacent. Politique fail-open : sans clé ou en cas d'erreur, aucun veto n'est appliqué — l'IA n'interrompt jamais le moteur par accident.

Moteur déterministe. Pour chaque sous-jacent autorisé, il calcule le régime de marché — écart relatif entre moyenne mobile 10 jours et 30 jours, comparé à un seuil de 3 % — puis en déduit la structure :

Régime → structure ouverte
Régime Structure d'options Thèse
Haussier Bull put spread encaisser la prime tant que le sous-jacent ne s'effondre pas
Baissier Bear call spread encaisser la prime tant qu'il ne s'envole pas
Neutre Iron condor encaisser la prime tant qu'il reste dans un couloir

strike jambe courte ≈ delta 0.30 (Black-Scholes, vol réalisée) · largeur $5 · échéance ≈ 7 j
prise de profit à 50 % du crédit · stop à 2× le crédit · clôture à DTE ≤ 1
spread directionnel clôturé si le régime bascule · iron condor laissé courir (anti-whipsaw)

Backtest de référence (6 sous-jacents, 17 mois, primes modélisées Black-Scholes) : rendement +2,1 %, drawdown max −7,2 %, Sharpe 0,36, 569 trades, 75,7 % gagnants. À lire comme un profil de comportement : le modèle sous-estime la prime réelle (vol implicite > vol réalisée) et la fenêtre de jugement est courte.

02

Points de contrôle des risques

Module risk_guard.py — déterministe, aucun LLM dans le chemin d'un ordre. Toute ouverture franchit la batterie complète ; le premier contrôle qui échoue bloque l'ordre et fournit la raison, journalisée.

  1. Compte paper obligatoire — refus sec sinon.
  2. Kill-switch perte du jour −15 % vs equity d'ouverture — bloque les ouvertures, autorise les clôtures.
  3. Kill-switch drawdown −30 % vs high-water mark.
  4. Risque défini uniquement — aucune jambe nue, jamais.
  5. Plafond de positions ouvertes 15.
  6. Perte maximale par structure $3 000.
  7. Exposition maximale par sous-jacent 35 % de l'equity.
  8. Buying power suffisant pour le collatéral.
  9. Buffer de cash plancher 2 % après collatéral.
  10. Fenêtre d'échéance DTE 2–60.
  11. Liquidité — spread bid-ask de la jambe courte ≤ 15 %.

Trois profils prédéfinis — conservative / balanced / aggressive (valeurs ci-dessus). Slippage modélisé à 3 % à l'entrée comme à la sortie. Le pire cas d'un trade est borné par construction : perte = largeur − crédit.

Infrastructure Alpaca

Trading API
SDK alpaca-py (paper) : compte & positions, get_option_contracts (chaîne filtrée type / échéance / strike), cotations OptionHistoricalDataClient, ordres multi-jambes OrderClass.MLEG + OptionLegRequest avec PositionIntent, bougies journalières (régime + vol réalisée).
Serveur MCP
Serveur MCP Alpaca connecté dans Claude Code pour la supervision en langage naturel — état du compte, positions, cotations, passage d'ordre manuel — pendant le développement et la démo.
Runner CLI
python -m src.run = point d'entrée autonome, planifié par GitHub Actions toutes les 20 min en heures de marché ; publie web/public/data/live.json.
Dashboard
Vite + React sur Netlify : courbe d'equity live, régimes, positions ouvertes, journal de décisions « pourquoi », trades du backtest.
Tests
66 tests pytest — garde-fou, pricing, machine à états, scénarios d'agent, backtest, analyste.
